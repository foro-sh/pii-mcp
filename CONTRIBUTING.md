# Contributing

Human-oriented guide for changing pii-mcp. Coding agents should prefer
[`AGENTS.md`](AGENTS.md) for commit and integration rules; this file covers
setup, adding a detector, and the checks a PR must pass.

## Setup

From a clone of the repo:

```bash
# Python (editable + tests)
pip install -e ".[dev]"

# Local Rust acceleration for Python (needed for eval/parity.py)
pip install -e ".[native]"
maturin develop --release --manifest-path crates/pii-mcp-native/Cargo.toml

# TypeScript package
(cd typescript && npm ci && npm run build)

# napi addon for the TypeScript package (needed for native TS tests)
(cd typescript && npm run build:native)

# Rust core unit tests
cargo test -p pii-core
```

## Adding a detector

A detector exists once per backend. All three must give the same output
(`python eval/parity.py` compares Python against Rust).

| Backend | Detector file | Register in the pack |
| --- | --- | --- |
| Rust | `crates/pii-core/src/detectors.rs` | `if has_<lang> { … }` near the end of that file |
| Python | `src/pii_mcp/detectors.py` | language pack list in `src/pii_mcp/scrub.py` (`_detectors_for`) |
| TypeScript | `typescript/src/detectors.ts` | language pack list in `typescript/src/scrub-js.ts` |

Also:

1. Add the rule to the module docstring at the top of each `detectors` file.
2. Update the AP coverage table (and intro list) in [`README.md`](README.md).
3. Add a generator under `PII` in `eval/generators.py`, plus hard negatives in
   `CLEAN` or `AMBIGUOUS` when the shape collides with other values.
4. Add tests in `tests/test_scrub_text.py` and `typescript/tests/scrub.test.ts`:
   one valid value, one failing check or format, one inside JSON or CSV.

Detector order matters: earlier matches become placeholders before looser
numeric detectors run. Match the order across all three backends.

Worked example: [#76](https://github.com/foro-sh/pii-mcp/pull/76) (US ITIN,
issue [#62](https://github.com/foro-sh/pii-mcp/issues/62)).

## Checks before a PR

```bash
python -m pytest tests                       # Python backend
(cd typescript && npm test)                  # TypeScript (js backend)
(cd typescript && npm run build:native && PII_MCP_BACKEND=native npm test)
cargo test -p pii-core                       # Rust core
pip install -e ".[native]"
maturin develop --release --manifest-path crates/pii-mcp-native/Cargo.toml
python eval/parity.py                        # Python and Rust agree
python eval/score.py                         # loss, false positives, ReDoS, perf
```

`eval/score.py` must print `"ok": true`.

Optional: `python eval/external.py` scores pii-mcp against a real-text sample
(`pip install -e ".[eval]"`; needs network access on first run). See its
module docstring for the dataset, license and scoring method.

## Commits and releases

Commits follow [Conventional Commits](https://www.conventionalcommits.org/).
The full rules (types, scopes, body wrapping, merge commits) are in
[`AGENTS.md`](AGENTS.md). A Git hook runs `commitlint` on every commit.

Versions and `CHANGELOG.md` are generated by release-please. Do not edit them
by hand.
